Remote management in three steps

  1. Start the hub.One container, reachable on your network. It keeps its data in a volume.
    docker run -d -p 8080:8080 -v material-choco-data:/data ghcr.io/ding-ding-projects/material-choco-hub:latest
    Running the hub in a container
  2. Create a pairing code.Open the hub, create the administrator, then make a code on the Machines page. It works once and expires after 10 minutes.
  3. Enter it on the Windows machine.In the app, or on a server without a desktop session:
    MaterialChoco.exe --agent enroll --hub https://your-hub --code XXXX-XXXX
MaterialChoco.exe --agent run
    Pairing and remote agents

Treat hub access as administrator access. The hub can install software with administrator rights on every paired machine. Serve it over HTTPS. Agents refuse plain HTTP to a remote hub unless you opt in for a trusted LAN. Read the security model before exposing a hub.

Honest status

  • Works and checked. The hub, agents, job queue, schedules, users and roles, passkeys, command allow lists, webhooks and the interface are covered by the automated tests (npm test) and by an end to end run that drives the real interface in a browser against a real hub and two agent processes. The hub image was built and run as a container. The release workflow built the installer on Windows with the repository's own CLI inside. The exact results are in the handoff note.
  • Not yet proven. Nobody has installed the app on Windows and run a real install, upgrade or uninstall through it. Every automated check so far used a test stand-in for choco.exe. Reduced motion, screen readers and display scaling have not been audited. Until the Windows proof exists, treat this as an early build.
  • Not signed. The installer is not code signed. Windows may warn about an unknown publisher.
  • Built, with limits you should know. Passkeys work in the automated checks with a software passkey device; nobody has signed in with a real device yet. Secret values are encrypted in the hub's data file, but the key lies in the same folder unless you move it. Not built: signed agent updates, limiting a user to some machines. The desktop app is written to download a newer release and announce it, but that has never run on Windows, so do not rely on automatic updates.
