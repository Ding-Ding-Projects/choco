Checked

  • The hub, agents and interface. Covered by the automated tests and by an end to end run that drives the real interface as admin, operator and viewer. This includes the job queue, schedules, users and roles, passkeys, command allow lists, status webhooks and secrets at rest.
  • The release. The workflow builds the Chocolatey CLI from this repository on Windows, packs it into the installer and publishes it, and pushes the hub image.
  • This site. Every internal link is checked each time the site is built, and every page was measured at phone and desktop widths for sideways scroll and small touch targets.

Not yet proven

  • Windows. Nobody has installed the app on Windows and run a real install, upgrade or uninstall through it. Every automated check used a test stand-in for choco.exe, on Linux. The two build scripts for Windows have never been run.
  • Passkeys on a real device. They were checked with a software passkey device and with the virtual one in Chrome.
  • Accessibility. Reduced motion, screen readers, display scaling and the larger text sizes have not been audited.
  • Automatic updates. The desktop app is written to download a newer release and announce it. That has never run on Windows.
  • Secrets at rest. Secret values are encrypted in the hub's data file, but the key lies in the same folder unless you move it.
