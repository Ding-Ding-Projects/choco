Checked

  • Windows, with the real CLI. On 2026-11-16 release 0.1.16 was downloaded, its SHA-256 sums compared with the release notes, and installed on Windows 11. With the Chocolatey CLI inside the app it installed, upgraded, pinned and uninstalled a package, turned a source and a feature off and on, and showed both full-screen results. The bundled CLI unpacked into the app's own folder and left a Chocolatey that was already on the machine untouched.
  • Automatic updates. An installed 0.1.15 found and downloaded 0.1.16 by itself within a minute, said that the build is not code signed, and started as 0.1.16 the next time.
  • The hub. The published container image ran, a Windows machine paired with a one time code, and a job started from a phone-width browser ran there with the real CLI.
  • The build scripts. From a clean clone on Windows, build-installer.bat built the CLI from source and produced an unsigned installer, and build.bat built and started the app.
  • The hub, agents and interface. Covered by the automated tests and by an end to end run that drives the real interface as admin, operator and viewer. This includes the job queue, schedules, users and roles, passkeys, command allow lists, status webhooks and secrets at rest.
  • This site. Every internal link is checked each time the site is built, and every page was measured at phone and desktop widths for sideways scroll and small touch targets.

Not yet proven

  • A fresh Windows. The machine used already had the .NET build tools that the CLI build needs, so a build on a machine with nothing installed is not proven.
  • Passkeys on a real device. They were checked with a software passkey device and with the virtual one in Chrome. Over plain HTTP on a LAN address browsers do not offer passkeys at all, so this needs the hub on HTTPS.
  • Accessibility. Screen readers and display scaling have not been audited. The clipping check covers text at 200 percent.
  • Working offline. The installed app was not tried without a network.
  • Secrets at rest. Secret values are encrypted in the hub's data file, but the key lies in the same folder unless you move it.
